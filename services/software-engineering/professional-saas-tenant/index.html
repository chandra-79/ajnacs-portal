Protect tenant boundaries through a feature change

A hypothetical engineering exercise tests authorization across list, detail, export and asynchronous paths.

#Hypothetical problem and baseline

A fictional professional-services SaaS team is adding document exports and wants engineers to preserve tenant isolation across synchronous and background work. The lab contains two invented firms and synthetic documents. It does not claim a real security assessment. The baseline asks participants to identify the authenticated actor, trusted tenant context and every path through which an export can be requested or retrieved.

#Design and delivery

The API checks authorization before creating an export job. The job stores a stable tenant and resource reference derived from trusted context, and the worker rechecks the relevant policy before producing the artifact. Download access is evaluated separately from job creation. A copied identifier or a changed query parameter must not grant access to another firm's document.

Participants use selected requirements from the OWASP Application Security Verification Standard to structure review. The instructor seeds a defect in a status endpoint that filters by job ID but omits tenant scope. Another fixture removes a user's permission after the job is queued. Learners must explain the intended behaviour rather than assume authorization at submission lasts forever.

#Synthetic evidence matrix

The invented matrix contains 20 boundary checks across four paths: five each for list, detail, export creation and artifact retrieval. In the deliberately vulnerable fixture, 17 checks produce the expected result and three expose cross-tenant access. The corrected capstone requires all 20 to match the defined policy. The chart compares 17 and 20 correct outcomes. These counts are teaching inputs, not a quantified real-world security risk.

The worksheet records actor, tenant, resource, route, expected decision and observed response. It includes negative checks and permitted operations so a fix that blocks every export cannot pass. Logs use synthetic identifiers and omit document contents. A passing test suite is evidence for the exercised boundaries, not proof that no undiscovered path exists.

#Acceptance, rollback and handover

Acceptance requires all declared boundary checks, correct delayed-permission handling, traceable job state and a clear explanation of the trust boundary. The participant adds a regression test around the real handler and data-access path. Mocking the authorization function to always allow access would invalidate the relevant security evidence.

The training environment cannot reach production storage and uses expiring credentials. Cleanup removes generated artifacts, queued jobs and test identities, including derivative files that a database deletion alone would leave behind. Handover includes the boundary matrix, fixtures, review notes and incident-style investigation steps. A delayed transfer exercise introduces a shared-document feature with explicit grants, requiring engineers to refine the policy rather than weaken tenant checks to make the new feature work.
